# Staged classroom raid

Teacher: configure ordered tasks, per-step rubric and evidence checks → open coding → pause/extend/close → immutable collective attack → feedback → retry or next task. Students work in their own IDE, push to GitHub and explicitly submit a branch/ref; the server resolves an immutable SHA and never grades fallback/cached HEAD profiles. Standard battle stays unchanged. Existing legacy edu simulation remains isolated from this new classroom flow.

Host projection: left 32% ranked roster, right 68% Boss and shared damage; top task/deadline, bottom teacher controls. Phones show the assignment, GitHub submission, private evidence and next actions; no sensor permission and no continuous arena rendering. At most 10 s of transform-only grouped attacks. Palette: ink #080d18, panel #101a2b, text #e8edf7, cyan #68d8ff, amber #ffd067, red #ff637a; existing VT323 for display and inherited monospace for readable body. Pass/connected uses existing brand green. Phase progression and changing scores carry the visual emphasis; avoid decorative dashboard cards.

Evaluation: stage-specific existing rubric plus explicit file-existence, literal-content and commit-bound GitHub check results. Literal checks are labelled static evidence, never reported as executed tests. Teachers can review actual functionality and record a score with a note. Arbitrary repository code is never executed on the host. No model/key prerequisite: actionable feedback is derived from the measured criteria and teacher task. Code/feedback details are private to each student and the teacher; public roster carries only scores, commit and contribution.

Server owns phase/timer, pending submission tickets, score freeze,10 s raid, cumulative boss damage, retry/next and reconnect. Teacher can't settle pending submissions or change an active plan. Deadline closes new submissions; pending requests drain before settlement. Four concurrent GitHub analyses across rooms, bounded room capacity 30, bounded task/round/submission history. Persistence stores plans and aggregate results, never repository source or detailed feedback. Restart pauses coding and completes an interrupted already-scored raid; students resubmit to retrieve detailed feedback. Teacher control requires the reserved teacher identity (ordinary student owner election cannot promote a student mid-class).

Acceptance: unit scoring/phase/timer/privacy/stale-result cases; protocol 30 student concurrent workflow and reconnect/restart; real browser teacher+students configure/submit/settle/feedback/retry/next/export; phone 390 px and projector 1920 px screenshots; full battle regression. Physical classroom and GitHub-provider quotas remain distinct from synthetic 30 student transport proof.
