# codex-repo: analysis/
You own `analysis/` and `data/fallback/`.
- `analyzeRepo(slugOrUrl)`: accept "owner/name", github URLs. Use GitHub REST (optional GITHUB_TOKEN env) for repo meta, languages, contributors count (per_page=1 + Link header trick), commit count (same trick). Download tarball (codeload.github.com/<slug>/tar.gz/HEAD), stream-extract in memory (node zlib + a minimal tar parser, no deps), skip vendored/node_modules/dist/binary files, cap size (~40 MB / 20k files).
- Import graph: regex-based import parsing for JS/TS (import/require/export from), Python (import/from), Go (import blocks, module path from go.mod), Rust (mod/use crate::), Java/Kotlin (package/import), C/C++ (#include "..."), Ruby (require_relative), C# (namespace/using best effort). Resolve to files where possible. Components = top-level dirs (if one dominant dir like src/ or packages/, go one level deeper), max 8 by LOC, rest merged into "misc". Heart = file with highest fan-in. edges between components, cycles = SCCs (Tarjan) size>1, maxDepth = longest path in condensed DAG. testRatio, seed = FNV-1a of slug.
- Cache results in `.cache/analysis/<slug>.json` (gitignored). Timeout -> fallback if slug in fallback set, else a deterministic synthetic profile from seed with `fallback: true` (never throw for a well-formed slug; throw only on garbage input).
- Precompute `data/fallback/*.json` for at least 12 famous repos across languages and shapes: facebook/react, vuejs/core, expressjs/express, pallets/flask, fastapi/fastapi, django/django, rust-lang/rustlings, BurntSushi/ripgrep, golang/example, gin-gonic/gin, torvalds/linux is too big (pick something like redis/redis), lodash/lodash, spring-projects/spring-petclinic, jquery/jquery, tensorflow/tensorflow too big -> pick karpathy/nanoGPT. Write `analysis/precompute.ts` to regenerate them.
- Vitest tests with tiny in-memory fixtures for the parser/graph.
