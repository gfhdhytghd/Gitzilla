# codex-gemini: design/
You own `design/`. Gemini designs every Kaiju's LOOK and FLAVOR (never stats).
- Key: read from env GEMINI_API_KEY, else parse `.env` in repo root, else `../.env` (key name there is `GEMINI-API-KEY` with hyphens — parse the file manually, accept both spellings). Never log the key. No key -> skip Gemini silently.
- REST `POST https://generativelanguage.googleapis.com/v1beta/models/${GEMINI_MODEL||"gemini-3.8-flash"}:generateContent` with header `x-goog-api-key`, `generationConfig.responseMimeType="application/json"` + `responseJsonSchema` (or `responseSchema`) built from the enums in shared/types.ts (HeroDesign, BossDesign). Use plain fetch, no SDK. Timeout ~8s, one retry with gemini-3.1-flash-lite on failure.
- `designHero(profile: RepoProfile, kit: PlayerKit): Promise<HeroDesign>` — prompt: you're the art director of a Soul Knight-like pixel game with a hacker/code aesthetic; design a cute chibi hero that embodies this repo (language, purpose from README, shape, quirks). Players must look heroic/cute.
- `designBoss(profile: RepoProfile, kit: BossKit): Promise<BossDesign>` — weird, eldritch, boss-like code monster embodying the repo's architecture (heart file, cycles = knots, components = limbs, contributors = eyes, age = moss/legacy). Must include attackNames for EVERY kit.attacks id and limbNames for EVERY kit.limbs id; hacky/dev-humor names (rm -rf, merge conflict, segfault...).
- Validate + clamp output (enums, hex colors, lengths, eyes 1..12, fill missing ids from kit). On any failure return a deterministic seed-based design (`fallbackHero/fallbackBoss`) so callers always get a design.
- `applyHeroDesign(kit, design) -> PlayerKit` (sets design, title, palette) and `applyBossDesign(kit, design) -> BossKit` (sets design, name, palette, theme, attack[].name from attackNames). Stats untouched.
- Cache by `${slug}:${seed}:${kind}:${playerCount-independent}` in `.cache/design/` so rematches/players reusing a repo don't re-call. Boss design must not depend on playerCount (server recomputes boss kit at start: re-apply cached design).
- Precompute designs for all data/fallback repos into `data/design/<slug>.{hero,boss}.json` (script `design/precompute.ts`) so offline demo still has Gemini art direction.
- Handoff: write the exact server wiring (where in setRepo/setBoss/start to call designHero/designBoss + apply) to docs/progress/codex-gemini.md under 'Handoff to codex-net'. analysis/ owner (codex-repo) is adding RepoProfile.readme/tree; until present, work without them.
- Vitest tests with mocked fetch. Live-call each of 3 repos once to verify, paste one sample hero + boss JSON into your progress file.
