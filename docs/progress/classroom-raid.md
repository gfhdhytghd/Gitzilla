# Staged classroom implementation · 2026-10-24

Implemented on top of `cc822a9` in `repo-kaiju`. Changes are local and uncommitted; production has not been changed by this work.

Teachers can configure 1–12 ordered tasks with instructions, timers, per-task rubrics and evidence checks. Up to 30 students use their own IDE and GitHub, submit a branch/tag/SHA, receive private measured feedback, and participate in a 10 second automatic collective attack. Teachers can pause, extend, review functionality with a recorded score/note, retry, advance and export frozen round results. The projector has a dense 30 person ranking and one shared Boss. Student phones have no battle input or snapshot stream, no arena renderer, and classroom audio is muted without changing the saved battle sound preference. The task’s scoring criteria are visible before submission.

The server resolves each submission to an immutable SHA, reads that archive directly, and accepts only GitHub check runs tied to that SHA. It does not execute arbitrary student code. File/literal evidence checks are not behavioral tests. Feedback comes from measured criteria, failed evidence checks and teacher review, rather than an LLM judging functionality. Four analysis slots bound simultaneous GitHub work; an actual classroom can still encounter GitHub provider quotas and archive limits. Failed live analysis never falls back to synthetic grades.

The teacher identity remains reserved across disconnects. Settlement waits for pending submissions. Stale/revoked results cannot change a settled round. A repeated score on the same task earns no additional Boss damage. Aggregate history and teacher/student resume identities survive server restart; coding pauses and private detailed feedback requires resubmission. CSV/Markdown downloads require the teacher’s room token and escape spreadsheet/markup injection.
